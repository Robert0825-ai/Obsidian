## 为什么这样布置

旧场景主要是素材试拼：地面能走，但墙、门、藤、灯、墓标和前景大多隐藏，玩家看不出一间完整关卡。

这次借参考图的四个构图特点：高墙、月光开口、藤蔓、前景遮挡；不照搬参考作品的具体墙面，也不引入参考图人物。

布置原则是“墙可以密，走路线必须清楚”：

- 大墙、树和远景负责压住空间。
- 小堂中央留月光开口，避免整间都一样黑。
- 墓标、棺材、灯等摆在路边，不给装饰物加阻挡碰撞。
- 前景只在两端挡一点腿，不连续盖住整条路。
- 地面保留裂、湿、泥路，也允许 `GroundMid` 等模块间隔重复；重复用来建立节奏，不是机械铺满。

## 商用重排（用户复查后）

第一版的问题不是“素材种类不够”，而是错误地把素材表当成陈列柜：钟、笼、井、长椅、棺材、石像等大件同时出现，导致每屏都很吵，玩家轮廓和路线不清楚。

第二版改为类恶魔城常用的模块节奏：

- 墙中段、铁栅、墓碑、壁灯、石栏和路面允许重复。
- 入口只留藤树与铁栅，小堂只留窗与吊灯，长廊只留钟楼，城堡只留城门。
- 井、笼、长椅、圣水盆、立棺、破石像等不删资源，只在本关隐藏。
- 重复小件，减少大件；用留白分区，不用“每张 PNG 必须出现”证明素材多。
- 删除有矩形裁切感的底部前景，只留顶部垂藤框景。

## 多路线修正（用户第二次复查后）

商用重排解决了“素材堆满”，但关卡碰撞仍是一条横线。用户指出：藤蔓不是纯装饰，而是爬绳；除开场外，墓园要能上下分流。

## 详细代码解释

### 1. 四区路标

```gdscript
[node name="关卡分区" type="Node2D" parent="Play"]
[node name="入口墓道_0到700" type="Marker2D" parent="Play/关卡分区"]
position = Vector2(350, 80)
```

`Marker2D` 是编辑器里的位置记号。`position` 的 `350` 是入口区中点附近，`80` 把标记放在画面上方。它不生成实体，也不会挡玩家。

### 2. 月光束

```gdscript
[node name="BeamWide" type="Polygon2D" parent="Play/Moonlight"]
polygon = PackedVector2Array(630, 70, 820, 70, 1120, 438, 700, 438)
color = Color(0.72, 0.67, 0.92, 0.08)
```

- `Polygon2D`：用几个点围成一个平面形状。
- `PackedVector2Array`：按顺序保存四个二维坐标，组成从上窄到下宽的光束。
- `Color(..., 0.08)`：最后一个数是透明度，只有 8%，所以是淡光而不是不透明色块。

人话：在月光小堂开口后面放一层很淡的紫灰光，墙仍然看得清。

### 3. 主路碰撞

```gdscript
[sub_resource type="RectangleShape2D" id="RectangleShape2D_walk"]
size = Vector2(3450, 36)

[node name="CollisionShape2D" type="CollisionShape2D" parent="Play/Walk"]
position = Vector2(1725, 438)
```

主路从 `x=0` 到 `x=3450`，所以矩形宽 `3450`，中心在一半 `1725`。碰撞中心 `y=438`，高度 `36`，顶面就是 `438 - 18 = 420`；测试玩家的脚落在 `y=420`。

### 4. 全程走跳验收

```gdscript
Input.action_press("Right")
for frame in range(1000):
	if frame == 180:
		Input.action_press("Jump")
	await physics_frame
```

`Input.action_press("Right")` 模拟一直按住右移。循环等待 1000 个物理帧，第 180 帧按一次跳。脚本会检查玩家是否掉到 `y>650`，以及最后是否走到 `x>3250`。

人话：不是只检查场景“能打开”，而是真的让测试角色从头走到尾并跳一次。

### 5. 藤蔓如何通知玩家

```gdscript
func _on_body_entered(body: Node2D) -> void:
	if body.has_method("enter_climb_zone"):
		body.enter_climb_zone()
```

`body_entered` 是玩家进入 `Area2D` 时发出的信号。`has_method` 先确认碰到的物体真的会攀爬，避免普通物体没有该函数时报错。

人话：藤蔓只负责说“玩家现在在可爬范围里”，不直接拖动玩家。

### 6. 玩家如何上下爬

```gdscript
var climb_axis := Input.get_axis("Climb", "Down")
velocity.y = climb_axis * climb_speed
```

`Climb` 是 W / ↑ / 手机摇杆上，返回负方向；`Down` 是 S / ↓ / 摇杆下，返回正方向。Godot 的 y 轴向下为正，因此负数会往上爬。

```gdscript
if Input.is_action_just_pressed("Jump"):
	is_climbing = false
	velocity.y = jump_velocity
```

人在藤上按跳，会退出攀爬并获得向上的跳跃速度。

### 7. 为什么上层平台是单向碰撞

```gdscript
one_way_collision = true
```

普通平台会挡住从下面往上爬的玩家；单向碰撞允许玩家从下方穿过，落下时才托住脚。这是“藤蔓穿过平台到上层”的关键。

## 房间图与玩家地图（2026-08-18）

八层货架能爬，但地图上看仍是一叠矩形。用户指定按这些工具来设计：

- [ManiaMap](https://mpewsey.github.io/ManiaMap.Godot/)：房间 = 格子集合，布局 = 图，门有方向，地图按格子画。
- [khrome/procedural-layouts](https://github.com/khrome/procedural-layouts)：房间可以蛇形，额外门打破线性。
- [KoBeWi/Metroidvania-System](https://github.com/KoBeWi/Metroidvania-System)：不规则房间 + 地图单元。
- [MVMap](https://github.com/TitaniumCladStudios/MVMap)：一个房间是任意 cell 集合（L 形、长走廊）。

ManiaMap 的 Godot 插件要 **Godot.NET（C#）**。firebot 现在是 GDScript，没有为这一关把整个工程改成 C#。所以**学它的数据模型，用现有节点实现**：`cemetery_map_layout.gd` 就是那张图。

### 为什么房间不是 8 条一样宽的地板

地面仍全宽（入口 → 墓道 → 城堡）。上面和下面按主题收窄：石像厅/井厅只有中间一格；停尸间、铁栏、骨室是两格；小堂和墓标长廊仍是横厅。空格子不进地图，轮廓才像 MV，不像货架。

回路：

1. 中井筒贯通（电梯）。
2. 左右井筒只连有地板的房间。
3. 左/右各有一条 `上3→上1` 跳层藤，可以绕过停尸间。

城堡仍然只有地面右侧那一座。

### 8. 世界坐标怎么变成地图格子

```gdscript
static func cell_of(world: Vector2) -> Vector2i:
	var cx := clampi(int(floor(world.x / CELL_W)), 0, COLS - 1)
	return Vector2i(cx, layer_index(world.y))
```

- `CELL_W = 1150`：整关宽 3450，横着切成 3 格。
- `layer_index`：用地面脚线 `y=420` 和层距 `300` 算出第几层，再加 3，让井厅是第 0 行、石像厅是第 7 行。

人话：地图不管精灵在哪，只问「脚在哪一格」。走到城堡那一段，格子就变成 `(2, 3)`。

语法点：`floor(world.x / CELL_W)` 是往下取整。`clampi` 防止走出关外时格子变成 -1。

### 9. 黄三角怎么跟着走

```gdscript
player_world = _player.global_position
player_facing = _player.facing
var marker: Vector2 = origin + layout.map_pos(host.player_world, cell_w, cell_h)
```

`_process` 每帧读玩家世界坐标。小地图和大地图用各自的格子宽高再算一遍屏幕位置。三角尖朝 `facing`（1 右，-1 左）。

人话：你在关里走，地图上的黄三角同步挪，不是过了门才瞬移一格。

### 10. 走过的房间才亮

```gdscript
revealed[current_room_id] = true
```

没去过的房间只画暗框。入口默认已亮。这是 MV 地图的最低雾。

## 2026-08-18 复杂房间图

用户要的不是 8 条货架，而是参考图那种：**很多房间、L 形、竖井、有的墙贴着却走不过去、有回路**。并且城堡放最上层；藤不要并排贯通；助手必须自己用主角跑一遍，每个房间都能进。

做法（代码，不是只画地图）：

- 8 列 × 8 层格子。房间是格子集合（28 间）。
- 横门才能走；竖门才放藤。BFS 从入口能到全部格子。
- 地面 4、5 列是洞。旧的全宽 `Play/Walk` 已禁用，不然会踩隐形地穿洞。
- 城堡 Y 从地面挪到上 4 脚线（墙约 `-852`）。
- 地图 `cemetery_map_layout.gd` 由重建脚本生成，避免再和场景对不上。

### 详细代码解释

房间进不进得去，看的是「格子图上有没有边」，不是看两间房画得近不近。

```python
if occ[a] == occ[b]:
    return True  # 同一间房的相邻格，能走
return (left, right, row) in h_door_set()  # 不同房必须有门
```

人话：两格挨着但没门，场景里会留空或立隔墙，主角走过去会掉或撞墙。

藤只在竖门上生成。同一层两根藤要错开，避免再变成三根井筒排排站。

```gdscript
static func cell_of(world: Vector2) -> Vector2i:
	var cx := clampi(int(floor((world.x - ORIGIN_X) / CELL_W)), 0, COLS - 1)
	var cy := clampi(int(round((GROUND_FOOT - world.y) / GAP)) + GROUND_ROW, 0, ROWS - 1)
	return Vector2i(cx, cy)
```

人话：用脚在哪一格，决定地图黄三角在哪一间。
