## 一、为什么要这么改？（原因，先读）

### 1.1 为什么不用方块 ◀▶？

| 问题 | 原因 |
|------|------|
| 丑、不像手游 | 市面横版动作手游左手几乎都是**圆形摇杆**或圆形方向盘 |
| 只有左右 | 攀爬需要**上 / 下**，方块键很难自然表达「斜推」 |
| 占位别扭 | 四个方块挤左下角，误触多、不像「一个控件」 |

所以改成：**一个圆盘 + 中间可拖的圆头（knob）**。

### 1.2 为什么上 = Climb、下 = Down？

| 摇杆方向 | 动作名 | 设计含义 |
|----------|--------|----------|
| ← / → | `Left` / `Right` | 左右走 |
| ↑ | `Climb` | **爬（向上）** |
| ↓ | `Down` | **向下爬 / 下** |

原因：

1. PC 上本来就有 `Climb`=W、`Down`=S，手机应对齐同一套暗号。  
2. 攀爬玩法以后做墙/梯子时，脚本继续听 `Climb`/`Down`，不必为手机再写一套。  
3. 「上爬 / 下爬」用摇杆推方向，比再点一颗「上」按钮更符合手游习惯。

> 注意：摇杆**已经发出** Climb/Down；若角色现在还不会爬墙，那是**玩法逻辑还没写**，不是摇杆没绑上。

### 1.3 为什么滑铲不放在摇杆旁边做组合键？

左手拇指已经在拖摇杆，再要求「按住方向 + 点下」会打架。  
所以：**滑铲放右手独立「滑」键**（动作名 `Slide`）。  
详见 [[手游操作-滑铲冲刺闪避常见做法]]。

### 1.4 为什么冲刺和闪避共用「冲」？

减少右手按钮数量；很多手游把短位移闪避和冲刺做成同一键（`Dash`）。以后要拆再拆。

### 1.5 改完之后的结构（人话）

```text
TouchControls（CanvasLayer，盖在游戏画面上）
├─ 左：Joystick（圆形摇杆脚本）
│     拖动 → Input.action_press("Left"/"Right"/"Climb"/"Down")
└─ 右：跳/攻/冲/滑 四个 Button
      按下 → 注入 Jump / Attack / Dash / Slide

玩家脚本（sword_player）仍然只写：
  Input.get_axis("Left","Right")
  Input.is_action_just_pressed("Dash")
  …
```

## 详细代码解释 · A）右侧虚拟键 `touch_controls.gd`

对照：`Sprite/ui/touch_controls.gd`

### A1）要不要在电脑上显示？

```gdscript
@export var show_on_pc_for_test: bool = true
```

| 词 | 人话 |
|----|------|
| `@export` | 检查器旋钮，可勾选 |
| `show_on_pc_for_test` | 开发期在 PC 也显示虚拟操作，方便鼠标试 |

**为什么默认 true：** 你还没天天导出 APK；不显示就没法在电脑上试手游键位。  
真机发布前可改 `false`：纯键鼠 PC 可隐藏；手机仍靠下面的平台判断显示。

### A2）何时显示整层 UI

```gdscript
func _should_show() -> bool:
	if show_on_pc_for_test:
		return true
	return (
		OS.has_feature("android")
		or OS.has_feature("ios")
		or OS.has_feature("mobile")
		or DisplayServer.is_touchscreen_available()
	)
```

| 词 | 人话 |
|----|------|
| `OS.has_feature("android")` | 当前是不是安卓包 |
| `is_touchscreen_available()` | 设备有没有触屏 |

**人话：** 开发开关开着 → 总显示；否则只在手机/触屏环境显示。

### A3）把按钮接到动作名

```gdscript
func _ready() -> void:
	_root.visible = _should_show()
	_wire_button(%BtnJump, "Jump")
	_wire_button(%BtnAttack, "Attack")
	_wire_button(%BtnDash, "Dash")
	_wire_button(%BtnSlide, "Slide")
```

| 词 | 人话 |
|----|------|
| `%BtnJump` | 场景里勾了「唯一名称」的按钮，用 `%名字` 找 |
| `"Jump"` | 要注入的动作名（必须和 InputMap / 玩家脚本一致） |

**为什么左键不在这里接线？** 左是摇杆自己负责 Left/Right/Climb/Down，不走 Button。

### A4）按下 / 松开时接线

```gdscript
func _wire_button(btn: BaseButton, action: StringName) -> void:
	btn.button_down.connect(_on_action_down.bind(action))
	btn.button_up.connect(_on_action_up.bind(action))
	btn.mouse_exited.connect(func() -> void:
		if btn.is_pressed():
			_on_action_up(action)
	)
```

| 词 | 人话 |
|----|------|
| `button_down` / `button_up` | 按钮按下 / 松开时发的信号 |
| `.connect(...)` | 信号来了就调用后面的函数 |
| `.bind(action)` | 预先塞好参数：到时调用 `_on_action_down("Jump")` |
| `mouse_exited` | 指针滑出按钮外 |
| `func() -> void: ...` | 匿名小函数（lambda） |

**为什么要 mouse_exited 也松开？**  
手指/鼠标按住拖出按钮外时，有的情况收不到 `button_up`，会**卡键**（一直以为 Jump 按着）。滑出去就强制松开。

### A5）注入动作事件（核心）

```gdscript
func _emit_action(action: StringName, pressed: bool) -> void:
	var ev := InputEventAction.new()
	ev.action = action
	ev.pressed = pressed
	ev.strength = 1.0 if pressed else 0.0
	Input.parse_input_event(ev)
```

| 词 | 人话 |
|----|------|
| `InputEventAction.new()` | 新建「动作事件」盒子 |
| `ev.action` | 暗号名，如 `"Dash"` |
| `ev.pressed` | true=按下，false=松开 |
| `strength` | 力度 0～1；按钮一般用满格 1 |
| `parse_input_event` | 把事件塞进引擎，全游戏都能 `is_action_pressed` 听到 |

**人话：** 不是读键盘键码；是**假装** Dash/Jump 被按了。  
**为什么用 `parse_input_event`：** 这样 `is_action_just_pressed` 也能在「按下那一帧」为真，和真键盘更像。

## 详细代码解释 · B）圆形摇杆 `virtual_joystick.gd`

对照：`Sprite/ui/virtual_joystick.gd`

### B1）旋钮参数（检查器可调）

```gdscript
@export var deadzone: float = 0.28
@export var base_radius: float = 78.0
@export var knob_radius: float = 34.0
```

| 参数 | 人话 |
|------|------|
| `deadzone` | 死区：摇杆头离中心太近时当「没推」，避免轻微抖动乱走 |
| `base_radius` | 外圈圆盘半径（像素） |
| `knob_radius` | 中间可拖圆头半径 |

**为什么要死区：** 手指很难精确停在正中心；没有死区会「站着也微微走路」。

### B2）运行中要记住的状态

```gdscript
var _dragging: bool = false
var _pointer_id: int = -1 ## 触屏 index；鼠标用 -2
var _knob_offset: Vector2 = Vector2.ZERO
var _current: Vector2 = Vector2.ZERO ## -1..1，y 上为负
```

| 变量 | 人话 |
|------|------|
| `_dragging` | 现在有没有在拖 |
| `_pointer_id` | 哪一根手指（多点触控时不串台）；鼠标约定用 `-2` |
| `_knob_offset` | 圆头相对圆心偏了多少（用来画） |
| `_current` | 归一化方向向量，给输入用 |

### B3）准备：接收点击、尺寸变化重画

```gdscript
func _ready() -> void:
	custom_minimum_size = Vector2(180, 180)
	mouse_filter = Control.MOUSE_FILTER_STOP
	resized.connect(queue_redraw)
```

| 词 | 人话 |
|----|------|
| `MOUSE_FILTER_STOP` | 这个控件要接住鼠标/触摸，不让点「穿透」到游戏世界 |
| `queue_redraw` | 下一帧重新调用 `_draw` 画圆 |

```gdscript
func _exit_tree() -> void:
	_release_all()
```

**为什么离开树要松开？** 换场景时若还按着摇杆，避免 Left 一直卡在「按下」。

### B4）收输入：手指 + 鼠标（电脑可测）

```gdscript
func _gui_input(event: InputEvent) -> void:
	if event is InputEventScreenTouch:
		...
	elif event is InputEventScreenDrag:
		...
	elif event is InputEventMouseButton and event.button_index == MOUSE_BUTTON_LEFT:
		...
	elif event is InputEventMouseMotion and _dragging and _pointer_id == -2:
		...
```

| 事件类型 | 人话 |
|----------|------|
| `InputEventScreenTouch` | 手指按下/抬起 |
| `InputEventScreenDrag` | 手指移动 |
| `InputEventMouseButton` | 鼠标键（PC 测试） |
| `InputEventMouseMotion` | 鼠标移动 |
| `accept_event()` | 这事件我吃了，别再传给后面 |

**人话流程：**

1. 在圆盘内按下 → `_begin_drag`  
2. 拖动 → `_update_drag`  
3. 抬起 → `_end_drag`（松开所有方向动作）

**语法点：** `event is InputEventScreenTouch` = 类型判断；为真后再 `as` 成具体类型用 `.pressed` / `.position`。

### B5）圆心与「点是否在盘内」

```gdscript
func _center() -> Vector2:
	return size * 0.5

func _in_base(local_pos: Vector2) -> bool:
	return local_pos.distance_to(_center()) <= base_radius + 12.0
```

| 词 | 人话 |
|----|------|
| `size * 0.5` | 控件宽高的一半 = 几何中心 |
| `distance_to` | 两点距离 |
| `+ 12.0` | 多给一点边缘宽容，更好点中 |

### B6）拖动时算方向（最重要的数学，用人话拆）

```gdscript
func _update_drag(local_pos: Vector2) -> void:
	var delta := local_pos - _center()
	var max_len := base_radius - knob_radius * 0.35
	if delta.length() > max_len:
		delta = delta.normalized() * max_len
	_knob_offset = delta
	var v := delta / max_len if max_len > 0.001 else Vector2.ZERO
	if v.length() < deadzone:
		v = Vector2.ZERO
	else:
		var len := (v.length() - deadzone) / (1.0 - deadzone)
		v = v.normalized() * clampf(len, 0.0, 1.0)
	_current = v
	_apply_to_input(v)
	queue_redraw()
```

逐步人话：

| 步骤 | 代码在干什么 |
|------|----------------|
| 1 | `delta = 手指位置 - 圆心` → 手指相对中心的偏移 |
| 2 | `max_len` → 圆头最多能拖多远（别拖出外圈太夸张） |
| 3 | 若超长 → `normalized() * max_len` 缩回圆内（只改长度，保留方向） |
| 4 | `_knob_offset = delta` → 记住圆头画在哪 |
| 5 | `v = delta / max_len` → 变成大约 -1～1 的方向向量 |
| 6 | 长度 &lt; 死区 → 当没推 |
| 7 | 否则去掉死区再映射长度 → 轻微推动不会「突然满速」 |
| 8 | `_apply_to_input(v)` → 写成 Left/Right/Climb/Down |
| 9 | `queue_redraw()` → 重画圆头位置 |

| 词 | 人话 |
|----|------|
| `.length()` | 向量长度（离中心多远） |
| `.normalized()` | 变成长度为 1 的同方向向量（只保留方向） |
| `clampf(x, 0, 1)` | 把 x 限制在 0～1 |

**坐标约定（易混）：**  
Godot 控件里 **y 向下为正**。所以：

- 手指往**屏幕上方**拖 → `v.y` 为**负** → 我们映射到 `Climb`  
- 手指往**屏幕下方**拖 → `v.y` 为**正** → 映射到 `Down`

### B7）向量 → 四个动作（上爬下爬在这里）

```gdscript
func _apply_to_input(v: Vector2) -> void:
	_set_action_strength(&"Right", maxf(v.x, 0.0))
	_set_action_strength(&"Left", maxf(-v.x, 0.0))
	_set_action_strength(&"Down", maxf(v.y, 0.0))
	_set_action_strength(&"Climb", maxf(-v.y, 0.0))
```

| 推法 | v 的大概值 | 谁被按下 |
|------|------------|----------|
| 右 | x&gt;0 | Right |
| 左 | x&lt;0 | Left（用 `-v.x`） |
| 下 | y&gt;0 | Down |
| 上 | y&lt;0 | Climb（用 `-v.y`） |

| 词 | 人话 |
|----|------|
| `&"Left"` | `StringName` 写法，动作名更省一点（和 `"Left"` 意思相近） |
| `maxf(a, 0)` | 只取正的那一半：右推时 Left 强度为 0 |

**为什么用 strength（力度）而不是只按死 0/1？**  
`Input.get_axis("Left","Right")` 能读到 0～1 的力度，走路可以更跟手（轻推慢、满推快——若玩家脚本用 axis 乘速度）。

### B8）真正按下 / 松开引擎动作

```gdscript
func _set_action_strength(action: StringName, strength: float) -> void:
	if strength > 0.02:
		Input.action_press(action, strength)
	elif Input.is_action_pressed(action):
		Input.action_release(action)
```

| 词 | 人话 |
|----|------|
| `Input.action_press(名, 力度)` | 告诉引擎：这个动作正按着，力度是多少 |
| `Input.action_release(名)` | 告诉引擎：松开了 |

**和右侧按钮的差别：**

| | 右按钮 | 摇杆 |
|--|--------|------|
| API | `InputEventAction` + `parse_input_event` | `action_press` / `action_release` |
| 适合 | 点一下（跳、冲） | 持续推着（走、爬） |
| 力度 | 通常 0 或 1 | 0～1 模拟量 |

两种都合法；目标都是让玩家脚本听到同一套动作名。

### B9）松手时四向全清

```gdscript
func _release_all() -> void:
	for action in [&"Left", &"Right", &"Down", &"Climb"]:
		if Input.is_action_pressed(action):
			Input.action_release(action)
```

**人话：** 手指一抬，不能还残留「一直在按右」。

### B10）画画：为什么是圆的

```gdscript
func _draw() -> void:
	var c := _center()
	draw_circle(c, base_radius, base_color)
	draw_arc(c, base_radius, 0.0, TAU, 64, ring_color, 3.0, true)
	# 十字参考…
	draw_circle(c + _knob_offset, knob_radius, knob_color)
```

| 词 | 人话 |
|----|------|
| `_draw` | 引擎要画这个控件时调用（你改了位置就 `queue_redraw`） |
| `draw_circle` | 画实心圆（底盘 / 摇杆头） |
| `draw_arc` | 画圆环边 |
| `TAU` | 一周弧度 = 2π，画满圆 |
| 十字线 | 淡淡提示上下左右，方便对准「上爬/下爬」 |

**为什么用代码画、不贴图？** 现在先有手感与结构；以后要精美皮肤，可换成 Texture，逻辑不用推翻。

## 详细代码解释 · C）玩家滑铲为什么认两路

对照：`Sprite/sword_player.gd`

```gdscript
var want_slide := Input.is_action_just_pressed("Slide")
if not want_slide and Input.is_action_just_pressed("Down") and absf(axis) > 0.01:
	if Input.is_physical_key_pressed(KEY_S) or Input.is_physical_key_pressed(KEY_DOWN):
		want_slide = true
if is_on_floor() and want_slide and slide_cooldown_left <= 0.0:
	_start_slide()
	return
```

| 条件 | 给谁用 | 人话 |
|------|--------|------|
| 刚按下 `Slide` | 手机「滑」、PC Ctrl | 朝当前 `facing` 滑，**不必**同时按方向 |
| 刚按下 `Down` 且左右轴非 0，**且**物理键 S/↓ 按下 | 仅 PC 键盘 | 方向 + S；摇杆注入的 Down **不算** |
| `is_on_floor()` | 都要 | 空中不滑铲（当前设计） |
| 冷却 &lt;= 0 | 都要 | 防止连滑刷屏 |

**为什么要加 `is_physical_key_pressed(KEY_S)`？（2026-08-11 修复）**  
摇杆推左下/右下时也会 `action_press("Down")` + Left/Right。若只判断动作名，会被当成「方向+S」而误触滑铲。  
市面手游：**摇杆斜下 ≠ 滑铲**；滑铲用右手键。  
`is_physical_key_pressed` 只认真实键盘键，不认摇杆注入的动作 → 斜推不再误滑。

**为什么要两路？**  
- 只保留「方向+S」→ 手机别扭。  
- 只保留 `Slide` → PC 玩家失去熟悉的下蹲滑。  
两路都指向 `_start_slide()`，**效果同一个函数**，不是两套滑铲逻辑。
冲刺：

```gdscript
if Input.is_action_just_pressed("Dash") and dash_cooldown_left <= 0.0:
	_start_dash()
```

手机点「冲」、PC 按 Shift，都走这里 → **冲 = 闪避**（当前设计）。

## 三、整条数据流（背这个就能串起来）

```text
【手机拖摇杆向上】
  → virtual_joystick 算出 v.y < 0
  → Input.action_press("Climb", 力度)
  → 任意玩家脚本 is_action_pressed("Climb") == true
  →（以后）爬墙逻辑用这个信号

【手机点「滑」】
  → touch_controls 注入 Slide 按下
  → sword_player want_slide = true
  → _start_slide() 朝 facing 滑

【PC 按住 D 再按 S】
  → 键盘 InputMap → Right + Down
  → sword_player 第二路 want_slide
  → 同一个 _start_slide()
```
