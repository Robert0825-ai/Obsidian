## 详细代码解释

### A. 为什么脚本写 `"Dash"` 不写 Shift

路径：`player/test_player.gd`

```40:41:player/test_player.gd
	if Input.is_action_just_pressed("Dash"):
		dash_left = dash_time
```

| 词 | 人话 |
|----|------|
| `Input` | Godot 的输入总管 |
| `is_action_just_pressed` | 「这一拍刚按下」，不是一直按着 |
| `"Dash"` | 动作名。引号里是名字，不是键 |

**人话：** 不管是 Shift、C，还是手机点「冲」，只要这一拍 `Dash` 刚亮，灰块就冲一下。

**语法点：** 圆括号里的 `"Dash"` 必须和 `project.godot` 里 `[input]` 的名字一模一样，包括大小写。

### B. 键位写在映射表，不写在玩家里

路径：`project.godot` 的 `Dash=` 那一段：第一个事件是 **Shift**（物理键码 4194325），第二个是 **C**（67）。`Left` / `Right` 里除了 A/D，还有 ← / →。

**人话：** 方向键没被拿掉。冲刺两把钥匙开同一把锁。

**语法点：** 改键 = 改这张表（或编辑器里的输入映射），不是改 `test_player.gd`。

### C. 屏幕按钮怎么假装成键盘

路径：`ui/touch_controls.gd`

```43:48:ui/touch_controls.gd
func _emit_action(action: StringName, pressed: bool) -> void:
	var ev := InputEventAction.new()
	ev.action = action
	ev.pressed = pressed
	ev.strength = 1.0 if pressed else 0.0
	Input.parse_input_event(ev)
```

| 词 | 人话 |
|----|------|
| `InputEventAction` | 一张「动作事件」卡片 |
| `ev.action = action` | 卡片上写 Jump / Dash / Pause… |
| `pressed` | `true` 按下，`false` 松开 |
| `StringName` | Godot 拿来当名字的短字符串，`&"Jump"` 那种 |
| `parse_input_event` | 把这张卡片塞进总管，假装玩家按了 |

**人话：** 手机没有 Shift 键。按钮按下时，我们印一张 `Dash` 卡片给总管。玩家脚本还是只问 `"Dash"`。

**语法点：** `%BtnJump` 是场景里勾了「唯一名称」的按钮。`%` = 按名字找，不必写长路径。

接线在 `_ready`：

```11:15:ui/touch_controls.gd
	_wire_button(%BtnJump, &"Jump")
	_wire_button(%BtnAttack, &"Attack")
	_wire_button(%BtnDash, &"Dash")
	_wire_button(%BtnSlide, &"Slide")
	_wire_button(%BtnPause, &"Pause")
```

**人话：** 五个按钮各自对应一个动作名。电脑上也显示（`show_on_pc_for_test`），方便你现在用鼠标试。以后真机包可以关掉，只留触屏。

### D. 摇杆怎么变成左/右/上/下

路径：`ui/virtual_joystick.gd`

```90:94:ui/virtual_joystick.gd
func _apply_to_input(v: Vector2) -> void:
	_set_action_strength(&"Right", maxf(v.x, 0.0))
	_set_action_strength(&"Left", maxf(-v.x, 0.0))
	_set_action_strength(&"Down", maxf(v.y, 0.0))
	_set_action_strength(&"Climb", maxf(-v.y, 0.0))
```

| 词 | 人话 |
|----|------|
| `v` | 摇杆方向，右为正 x，下为正 y（屏幕坐标） |
| `maxf(v.x, 0.0)` | 只取向右的那一半；向左时这段为 0 |
| `Climb` | 摇杆往上 = 爬（以后爬树用） |
| `action_press` | 按住这个动作，并带力度 0～1 |

**人话：** 圆盘往右推，总管收到 `Right`；往左推收到 `Left`。玩家那行 `Input.get_axis("Left", "Right")` 不用改。

**语法点：** `&"Right"` 的 `&` 表示 StringName。`maxf` 的 `f` = 浮点数。

### E. Esc 为什么能停游戏、菜单还能点

路径：`ui/pause_menu.gd`

```40:47:ui/pause_menu.gd
func _open_pause() -> void:
	_release_gameplay_actions()
	_menu_open = true
	_dim.visible = true
	_panel.visible = true
	_settings.visible = false
	_dim.mouse_filter = Control.MOUSE_FILTER_STOP
	get_tree().paused = true
```

| 词 | 人话 |
|----|------|
| `get_tree()` | 整棵场景树 |
| `paused = true` | 默认会停的节点停掉（玩家不再 `_physics_process`） |
| `_dim` | 半透明黑布，挡住后面 |
| `MOUSE_FILTER_STOP` | 鼠标点在黑布上，不要点到后面的游戏 |
| `_menu_open` | 我们自己记「菜单开着」，因为整层 CanvasLayer 一直显示，不能靠它的 visible 判断 |

场景里暂停菜单写了 `process_mode = 3`（ALWAYS）：

**人话：** 游戏停了，菜单这一层还醒着，所以「继续」能点。若菜单也跟着停，点了没反应。

**语法点：** `paused` 是树的开关，不是某一个按钮的开关。玩家没改 `process_mode`，所以跟着停。

打开设置只藏中间三个按钮、放出说明，**不改** `paused`（还是停着）：

```65:67:ui/pause_menu.gd
func _open_settings() -> void:
	_panel.visible = false
	_settings.visible = true
```

退出：

```75:76:ui/pause_menu.gd
func _quit() -> void:
	get_tree().quit()
```

**人话：** `quit()` = 关掉游戏窗口。测试场这样够。以后若要回标题页，再改成切场景。
