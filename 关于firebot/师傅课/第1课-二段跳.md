## 这节课要搞懂什么

人话三句：

1. 身上记一个数字：**空中还能跳几次**
2. **站在地上** → 把次数补满
3. **按跳跃键** → 在地上就一段跳；在空中且还有次数就二段跳，并减 1

按键：输入映射里的 `Jump`（一般是空格）。

## `@export` / `@export_group` 详解

- `@export`：把变量变成检查器里的旋钮（调参不用改代码）。
- `@export_group("Jump")`：只负责界面分组，**不负责跳跃逻辑**。
- 例：`@export var jump_velocity: float = -420.0`  
  - `var` = 变量  
  - `jump_velocity` = 名字  
  - `: float` = 小数  
  - `= -420.0` = 默认值（向上）

### 为什么要这些参数

| 参数 | 为什么存在 |
|------|------------|
| `jump_velocity` | 地面跳多高，要能拧 |
| `enable_double_jump` | 有的关卡要关二段跳 |
| `max_air_jumps` | 上限：1=二段，2=三段 |
| `double_jump_velocity` | 空中再跳力度，常略弱于一段 |

---

## 两个盒子：规矩 vs 现状

| 名字 | 像什么 | 会不会 `-1` |
|------|--------|-------------|
| `max_air_jumps` | 规则：最多几次 | **不会** |
| `_air_jumps_left` | 口袋：还剩几次 | **会** |

落地：`剩余 = 上限`。空中跳成功：`剩余 -= 1`。  
不要对上限做 `-1`，否则规矩会被越改越小。

## 核心逻辑

### 每帧（在地上回满 / 空中加重力）

```gdscript
func _physics_process(delta: float) -> void:
	_process_normal(delta)
	move_and_slide()

func _process_normal(delta: float) -> void:
	if is_on_floor():
		_air_jumps_left = max_air_jumps
	else:
		velocity.y += gravity * delta

	if Input.is_action_just_pressed("Jump"):
		_try_jump()
```

- `move_and_slide()`：让 `velocity` 变成真正移动，并更新是否在地面。
- 必须用引擎约定的 `_physics_process`，自创名字不会被自动调用。

### 按跳判断树

```gdscript
func _try_jump() -> void:
	if is_on_floor():
		velocity.y = jump_velocity
		return  # 一段跳不扣空中次数
	if enable_double_jump and _air_jumps_left > 0:
		velocity.y = double_jump_velocity
		_air_jumps_left -= 1
```

调用函数必须加括号：`_try_jump()`。只写 `_try_jump` 等于「提到名字但没执行」。

### 时间线（max_air_jumps = 1）

1. 站地 → 剩余被补成 1  
2. 空格 → 一段跳，剩余仍是 1  
3. 空中再空格 → 二段跳，剩余 0  
4. 再按 → 无  
5. 落地 → 剩余又变 1

## 详细代码解释

> 2026-08-11 回填。对照：`Sprite/fighter_player.gd`（练习稿）  
> 结构：小段代码 → 名词/小表 → 人话 → 语法点

### 1）每物理帧：引擎会自动叫这个名字

```gdscript
func _physics_process(delta: float) -> void:
	_process_normal(delta)
	move_and_slide()
```

| 词 | 人话 |
|----|------|
| `_physics_process` | 引擎约定的函数名：每物理帧自动调用；名字写错 = 永远不会跑 |
| `delta` | 这一帧过了多少秒（小数），用来做「乘时间」的计算 |
| `-> void` | 这个函数不往外交回一个值 |
| `_process_normal(delta)` | 先跑我们自己写的「普通逻辑」（重力、跳等） |
| `move_and_slide()` | 把 `velocity` 变成真正位移，并更新是否踩地 |

**人话：** 每一小段时间：先算速度该怎么变，再让人真正动起来、贴地。

**语法点：** 前导下划线 `_` 在 Godot 里常表示「引擎回调/内部用」；`()` 表示真正调用。只写 `_process_normal` 不带括号 = 提到名字但没执行。

---

### 2）落地补次数 / 空中加重力

```gdscript
if is_on_floor():
	_air_jumps_left = max_air_jumps
else:
	velocity.y += gravity * delta
```

| 词 | 人话 |
|----|------|
| `is_on_floor()` | 脚现在踩着地板吗？（要先 `move_and_slide` 才准） |
| `_air_jumps_left` | 口袋：空中还剩几次跳 |
| `max_air_jumps` | 规矩：最多几次（检查器旋钮，一般不拿来 -1） |
| `velocity.y` | 竖直速度；在 Godot 2D 里**向上常是负数** |
| `gravity * delta` | 重力加速度 × 这一帧秒数 = 这一帧该加多少下落速度 |

**人话：** 踩地就把「还能跳几次」补满；在空中就持续往下落得更快一点。

**语法点：** `+=` 表示「在原有基础上再加」；`A = B` 是「把 B 的值装进 A」，不会自动联动——所以要每帧踩地时重新赋值补满。

---

### 3）刚按下跳跃才尝试跳

```gdscript
if Input.is_action_just_pressed("Jump"):
	_try_jump()
```

| 词 | 人话 |
|----|------|
| `Input` | 问询键盘/手柄的入口 |
| `is_action_just_pressed("Jump")` | 输入映射里的 `Jump`，**刚按下那一瞬**为真 |
| `_try_jump()` | 去执行「尝试跳跃」那一包判断 |

**人话：** 不是每帧都在跳；只有刚按下跳跃键的那一下，才问「现在允不允许跳」。

**语法点：** `"Jump"` 必须和项目输入映射里的动作名一致；`just_pressed` ≠ `pressed`（后者按住会一直为真）。

---

### 4）判断树：一段跳 vs 二段跳

```gdscript
func _try_jump() -> void:
	if is_on_floor():
		velocity.y = jump_velocity
		return
	if enable_double_jump and _air_jumps_left > 0:
		velocity.y = double_jump_velocity
		_air_jumps_left -= 1
```

| 词 | 人话 |
|----|------|
| `jump_velocity` | 地面跳给的向上速度（负数） |
| `return` | 函数到此结束；后面二段跳逻辑本轮不再跑 |
| `enable_double_jump` | 开关：允不允许空中再跳 |
| `and` | 并且：两边都真才继续 |
| `> 0` | 口袋里还剩次数 |
| `-= 1` | 口袋减一张票 |

**人话：**

1. 在地上 → 给一段跳速度，然后结束（**不扣**空中次数）  
2. 在空中且开关开着且还有票 → 给二段跳速度，并扣 1 票  
3. 否则 → 什么都不做（哑火）

**语法点：** 地面分支的 `return` 很关键：没有它，若逻辑写乱，可能一段跳后又误跑后面。当前写法是「地上处理完就离开函数」。

---

### 5）规矩 vs 剩余（对照表，背这个）

| | 规矩（少改） | 剩余（常改） |
|--|-------------|--------------|
| 名字 | `max_air_jumps` | `_air_jumps_left` |
| 像什么 | 规定口袋最多几张票 | 口袋里现在几张 |
| 何时变 | 你在检查器拧 | 落地补满；空中跳成功 -1 |

## 问答记录

### Q：`max_air_jumps` 为什么看不到 `-1`？

减的是 `_air_jumps_left`（剩余），不是 `max_air_jumps`（上限）。上限是规矩，剩余是口袋里的票。

### Q：为什么要拆成两个变量这么写？

规矩几乎不变；现状会变。若只对一个数 `-1`，落地后不知道补回几，也容易把上限改坏。

### Q：`@export_group("Jump")` / `@export` 是企业级吗？为了即插即用吗？

主要是 **检查器好调、调参友好**，不等于整套企业架构。`@export` 把参数变成旋钮；`group` 只负责分组显示。

### Q：怎么监听按了哪个键？

推荐：`Input.is_action_just_pressed("Jump")`（听输入映射里的动作名）。  
不要写半截 `if input`。调试可看 `_unhandled_input` 打印键码。

### Q：代码长什么样、要从何学起？

用 Godot + GDScript；小脚本 → F5/F6 → 看输出 → 再多写一行。先 `print`，再 Input，再接到角色移动/跳跃。
