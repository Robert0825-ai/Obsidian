## 师傅这课的判断（先看这四句）

1. **逐帧画（现在这条路）必须锁参考。** 标准图是 `四脚猫/idle.png`。后面每张只改姿势，不改这只猫。
2. **锁骨也能解决「两只不同的猫」。** 因为动的是同一张皮，不是每帧重新画一只。它**不会**弄坏 Godot 里已经写好的跳/冲/滑；换的是「怎么播画面」，不是「怎么走路」。
3. **现在先不上骨。** 你还没点头选皮。骨是以后的工具，不是今天必须做的事。
4. **猫可以更清楚；游戏做大了，真正吃性能的通常不是「像素还是插画」这四个字，而是「每帧一张很大的图、动作又很多」。** 一只猫、合理尺寸，PC 和手机都扛得住。

## 2. 锁参考是什么（逐帧这条路的底线）

生成图**不是**「同一张 PNG 把腿掰一下」。每一次生成，模型都在**重新画一只猫**。你只说「黑猫」，它就会从很多种黑猫里抽。所以会出现：这一帧眼睛大、下一帧眼睛小；这一帧项圈红、下一帧项圈暗。

**锁参考** = 每次生成都把 `idle.png` 塞进去当「必须长这样」，文字只写「姿势改成走路/跳跃」。

标准图路径：

`C:\Users\yehai\Documents\游戏素材\像素猫\四脚猫\idle.png`

规矩：

- **不要覆盖** `idle.png`（它是尺子，不是草稿）
- 更清楚的试稿另存：`idle_clearer_test.png`（仍是像素、格子更利落）、`idle_hd_test.png`（离开像素、插画更清楚）
- 你点头某张更好看，再把它升成新的标准图

这已经写进 Cursor 规则 `pixel-cat-look-lock.mdc` 和用户规则「像素猫锁死外观」。

## 3. 锁骨是什么；能不能也解决「两只猫」

**锁骨**（人话）= 给猫装骨架，再把画好的皮贴在骨头上。摆腿时，皮跟着骨头弯。英文常见说法是 **rig / bones**。Godot 里这套节点叫 `Skeleton2D`；Spine 软件里也是绑骨。

| | 逐帧 + 锁参考 | 锁骨（Skeleton2D 或 Spine） |
|--|----------------|------------------------------|
| 同一只猫？ | 靠标准图；AI 仍可能漂一点 | **天生同一只**：皮只画一次 |
| 走路怎么来 | 一张一张生成/手绘 | 摆腿、摆尾巴 |
| 现在 firebot | 正好用 `AnimatedSprite2D` 换图 | 要把「播帧」换成「播骨骼动画」 |
| 适合什么时候 | 你还在选皮、试样子 | 皮已经定了，要做一整套动作 |

所以：**锁骨能解决这个问题**，而且通常比「每帧求 AI 别漂」更稳。  
但锁骨**解决不了**「皮还没选好」：你得先有一张（或拆好的几张）确定的猫，再绑。

**会不会影响以后 Godot 的动画？**

- **不会弄坏跳、冲、滑。** 那些写在 `CharacterBody2D` 上，管的是「人往哪飞」，不管身上贴的是逐帧图还是骨头。
- **会换「播画面」那一层。** 现在是 `AnimatedSprite2D` 播 `Idle` / `Jump` 这些**动作名**。上骨以后，多半改成 `AnimationPlayer` 播同名动作，或 Spine 的播放器。动作名尽量还叫 `Idle`、`Jump`，脚本少改。
- **第3课残影要改一小处。** 残影现在是「把当前这一帧的图复制出来」。骨头没有「当前这一帧 PNG」，要想别的办法（复制整只猫节点，或先截一张）。手感课还在，残影课要补一刀。

**今天不上骨。** 你还在看「像素清楚一点」还是「插画清楚一点」。皮没锁，绑骨是白绑。

## 4. 猫能再清楚一点吗？性能呢？

能。清楚有两档，本课各出了一张**试稿**，都没覆盖 `idle.png`：

| 文件 | 还是不是像素 | 观感 |
|------|----------------|------|
| `idle.png` | 是（当前标准） | 格子明显，远看像小黑块 |
| `idle_clearer_test.png` | 还是像素 | 同一只猫，轮廓更利落一点 |
| `idle_hd_test.png` | **不是像素了** | 同一配色同一姿势，脸和毛更清楚；试稿多了粉鼻子，**没锁死** |

**性能（人话，不要被吓到）：**

独立 2D 游戏里，一只猫很少把电脑拖死。卡不卡，主要看：

1. **每张图有多大**（64×64 很小；1024×1024 一张大约几 MB 量级）
2. **有多少张不重复的图**（8 个动作 × 8 帧 = 64 张；如果每张都是 2K，手机显存会开始不舒服）
3. **屏幕上同时画多少个**（一只主角 + 几个怪，没事；同屏 200 个高清大图才肉疼）

粗账（方便有感觉，不是精确测分）：

| 方案 | 大概多重 | 游戏做大了 |
|------|----------|------------|
| 小像素猫（角色高约 32～64 像素） | 很轻 | 几乎不用担心 |
| 高清像素（角色高约 80～128 像素，Nearest 放大） | 仍然轻 | 一套动作也没事 |
| 每帧一张 1024 插画，动作又很多 | 开始占内存 | **一只主角通常仍能做**；怪也全套高清逐帧，手机才容易胀 |
| 锁骨 + 一张（或几张）皮 | 往往比「几十张大图」更省 | 适合以后做大 |

结论：

- **为了好看离开像素，可以。** 一只高清猫当主角，firebot 这种体量，PC 没问题，手机也多半没问题。
- **不要**一上来每个动作都做 2K、每帧一张还不压缩。角色放进游戏时，常用 256～512 高就够看。
- 以后关卡多、怪多，优先：图集（把小图拼成一张大图）、怪用更少帧或也改绑骨。不是「插画这个风格本身有毒」。

Godot 里像素要用 **Filter = Nearest**（最近邻），格子才不糊。插画可以开过滤，让边软一点。这是导入设置，不是改脚本。

## 详细代码解释

工程还是现在的 Fighter，猫还没换进去。下面讲的是：**画面层在哪、为什么上骨只动这一层、残影哪一行会受影响、导入过滤是什么。**

### A. 角色身体 vs 身上那层皮

```1:6:C:\Users\yehai\Documents\firebot\Sprite\fighter_player.gd
extends CharacterBody2D
## 第1～3课练习：二段跳 + 无敌帧 + 残影制作入门
## 默认键位见项目输入映射 / Obsidian「按键绑定」：A/D 走，空格跳，F 挨打测试，V 无敌开关，W 出一张残影

## 找到角色身上「会播动画的那一层」
@onready var anim: AnimatedSprite2D = $AnimatedSprite2D
```

| 词 | 全称/来历 | 人话 |
|----|-----------|------|
| `CharacterBody2D` | 2D 角色身体 | 会撞地、会 `move_and_slide` 的那一层 |
| `AnimatedSprite2D` | 会播多帧图的精灵 | 身上贴的「动画片」 |
| `@onready` | 等节点准备好再赋值 | 进游戏后才去抓 `$AnimatedSprite2D` |
| `$AnimatedSprite2D` | 路径简写 | 找**自己身上**名叫 AnimatedSprite2D 的孩子 |

**人话：** 跳多高写在这个脚本里。猫长什么样写在 `AnimatedSprite2D` 的图里。换猫、换骑士、上骨，都是换「播画面」；**不要改 `extends CharacterBody2D`。**

**语法点：** `extends` = 我是哪种节点。`$名字` 的 `$` 是 Godot 快捷写法，等于 `get_node("AnimatedSprite2D")`。`:` 后面是类型，告诉电脑 `anim` 是 AnimatedSprite2D。

### B. 场景里挂着哪本「帧字典」

```415:418:C:\Users\yehai\Documents\firebot\Scene\fighter_player.tscn
[node name="AnimatedSprite2D" type="AnimatedSprite2D" parent="." unique_id=1502781109]
sprite_frames = SubResource("SpriteFrames_618we")
animation = &"Jump"
autoplay = "Idle"
```

（文件里大约在 415～418 行；你若增过节点，行号会略偏。）

| 词 | 人话 |
|----|------|
| `sprite_frames` | 一本字典：Idle 有哪些图、Jump 有哪些图 |
| `autoplay = "Idle"` | 一进游戏先播待机 |
| `&"Jump"` | 带 `&` 的字符串，Godot 叫 StringName，用来当动画名，查找更快 |

**人话：** 以后猫换进来，改的是这本字典里的**图**，尽量不改 `"Idle"` 这种**名字**。上骨的话，这个节点可能换成 `Skeleton2D` + `AnimationPlayer`，但父节点还是现在这个角色。

**语法点：** `parent="."` 的 `.` 表示「父节点就是这个场景的根」（玩家自己）。引号里的 `Idle` 必须和脚本里 `play("Idle")` 对得上，差一个字母就播不了。

### C. 待机动画名（换皮时不要改这个字）

```285:286:C:\Users\yehai\Documents\firebot\Scene\fighter_player.tscn
"loop": 1,
"name": &"Idle",
```

**人话：** `loop: 1` 表示循环播（待机一直呼吸）。名字是 `Idle`。猫的待机图将来塞进这一组的 `texture` 列表。

**语法点：** `.tscn` 是场景文本。`"name": &"Idle"` 左边是字段名，右边是动画名字。

### D. 残影：逐帧能用，上骨要改

```77:84:C:\Users\yehai\Documents\firebot\Sprite\fighter_player.gd
func spawn_one_afterimage() -> void:
	# 1) 没有动画节点就没法复制样子
	if anim == null or anim.sprite_frames == null:
		print("没有 AnimatedSprite2D，做不了残影")
		return

	# 2) 取出「当前这一帧」的图片
	var tex: Texture2D = anim.sprite_frames.get_frame_texture(anim.animation, anim.frame)
```

| 词 | 人话 |
|----|------|
| `func` | 定义一个功能 |
| `-> void` | 做完不返回值 |
| `sprite_frames` | 那本帧字典 |
| `get_frame_texture` | 取出某一动画、第几帧的图 |
| `anim.animation` | 现在正在播哪个动作（比如 Jump） |
| `anim.frame` | 现在是第几张（从 0 数） |
| `Texture2D` | 一张 2D 图 |

**人话：** 残影是「把现在这张图再贴一张在原地」。所以 **只要还是 AnimatedSprite2D 逐帧**（像素猫或高清猫都一样），这几行不用改。  
**如果改成锁骨**，没有 `sprite_frames` 这一帧一张图，这几行会失效，要另写（例如把整只猫 `duplicate()` 一份当残影）。这就是「不影响跳冲滑，但影响残影这一处」。

**语法点：** `.` 是「点谁身上的东西」。`anim.frame` = 动画节点的当前帧号。`==` 是比较是不是相等。`or` 是或者。

### E. 残影怎么贴上去（上骨后这一段思路还在）

```89:95:C:\Users\yehai\Documents\firebot\Sprite\fighter_player.gd
	var ghost := Sprite2D.new()
	ghost.texture = tex
	ghost.global_position = anim.global_position  # 停在「现在这个位置」
	ghost.flip_h = anim.flip_h                    # 左右朝向一致
	ghost.z_index = z_index - 1                   # 画在角色后面一点
	ghost.modulate = ghost_color                  # 换色/半透明，看起来像残影
```

| 词 | 人话 |
|----|------|
| `Sprite2D.new()` | 新建一个只会贴一张图的节点 |
| `:=` | 声明并赋值，类型让电脑猜 |
| `global_position` | 在整个游戏世界里的坐标 |
| `flip_h` | 水平翻转（面向左还是右） |
| `z_index` | 谁画在谁前面，数字大的在上面 |
| `modulate` | 给整张图乘一个颜色（含透明度） |

**人话：** 逐帧时，残影是一张 `Sprite2D`。上骨后，残影可能是「复制出来的一棵骨头树」，但「停在原地、半透明、过一会儿删掉」这套想法不变。

**语法点：** `:=` 的 `:` 表示新变量。`z_index - 1` 的 `-` 是减，让影子在角色后面。

### F. 以后上骨时，播动画会长这样（现在工程里还没有，先认字）

```gdscript
@onready var anim_player: AnimationPlayer = $AnimationPlayer

func play_jump_visual() -> void:
	anim_player.play("Jump")
```

| 词 | 人话 |
|----|------|
| `AnimationPlayer` | Godot 自带的「播放时间轴」节点，能播骨骼、也能播别的属性 |
| `play("Jump")` | 开始播名字叫 Jump 的那条动画 |

**人话：** 和现在用动作名 `Jump` 是同一句话。物理跳仍然是 `_try_jump()` 里改 `velocity.y`。画面跳是 `play("Jump")`。两件事分开，所以锁骨**不挡**以后做动画，只是播放器换一个。

**语法点：** 引号里的 `Jump` 必须和 AnimationPlayer 面板里那条动画的名字完全一样。

### G. 导入过滤（像素清楚 vs 插画清楚）

Godot 导入 PNG 时会生成旁边的 `.import` 文件，里面有一行类似：

```
filter=false
```

或导入面板里的 **Filter / Nearest**。

| 设置 | 人话 | 什么时候用 |
|------|------|------------|
| Nearest / filter 关掉 | 放大时一个格子还是一个格子，不糊 | 像素猫 |
| 开过滤（线性） | 放大时边会软、会糊一点 | 插画猫更自然 |

**人话：** 「清楚」有两种：像素是「格子利落」；插画是「线光滑、细节多」。导错过滤，像素会变成一摊泥，插画有时会锯齿。这是资源设置，不是 `fighter_player.gd` 里的代码。

**Q（2026-08-15）：所以要锁参考是吗？写下来。猫要不要锁骨？锁骨能不能也解决两只猫？会不会影响 Godot 动画？猫能更清楚吗？游戏做大会不会卡？**  
**A：** 逐帧必须锁参考，已写入规则和笔记。锁骨也能让永远是同一只猫，且不破坏跳冲滑，只换播画面层、残影要另写；皮没定以前不上骨。清楚可以：像素更利落、或离开像素做插画；一只猫合理尺寸做大了也不该卡，怕的是「每帧一张超大图 × 很多动作 × 很多角色」。试稿已另存，等你选。

**Q（2026-08-15）：先锁骨做动画，再导出帧/表/未分割，Godot 会更流畅吗？**  
**A：** 见 [[第8课-锁骨做动画再导出帧]]。大方向对；活骨骼比烘几张再切更滑；表当导出。
