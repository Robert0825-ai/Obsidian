## 师傅这课的判断（先看这四句）

1. **你的大方向对。** 用骨头做出走/跳，再导出帧，能避免「每一张都是另一只猫」，动作也会比 AI 逐帧顺。
2. **Godot 播帧图不会自动补中间姿势。** 它只是把第 1 张换成第 2 张。流畅不流畅，取决于你烘了多少张、间距好不好。骨头真正强的地方，是 **在 Godot 里直接播骨骼**——每秒几十次中间姿势都是算出来的。
3. **帧图 / 精灵表 / 未分割图要留，但是导出备份。** 能拉的骨头工程才是正本。只留 PNG、扔了骨头，以后改一个抬腿就要整套重画——火柴人那次已经踩过。
4. **皮还没定，今天不拆件。** 管线定了；先选 `idle` / 更清楚像素 / 插画，再绑。

## 2. 僵硬到底从哪来（不是 Godot「生成动画」笨）

现在玩家脚本 **`fighter_player.gd` 里甚至没有 `anim.play("Walk")` 这种切动作**。场景里写了 `autoplay = "Idle"`，所以进游戏多半一直在播待机那几张 Fighter 图。Godot **不会**根据你跳了就自动「生成」一套流畅猫动画。

`AnimatedSprite2D` 做人话就是：**到点了，把这一张 PNG 换成下一张 PNG。** 中间没有「腿从这里滑到那里」。

所以僵硬通常来自三件事：

| 原因 | 人话 |
|------|------|
| 帧太少 | 走路只有 4 张，看起来像在闪 |
| 每一张不是同一只 / 间距乱 | AI 逐帧最容易这样 |
| 没有缓入缓出（easing） | 腿匀速切，看起来机械 |

骨头能治后两件，也能让你**按需要多烘几张**。  
但它**不能**让「只有 4 张的精灵表」在 Godot 里自己变顺——除非你在 Godot 里**直接播骨头**，别先切成 4 张。

## 3. 师傅怎么看你这条管线（可以 / 真正强在哪 / 差距 / 对照）

按你喜欢的「更强工具」来说：

| | |
|--|--|
| **用它做你说的事** | **可以。** 锁骨 → 做 Idle/Walk/Jump… → 导出单帧、未分割、精灵表。这是游戏公司常用的「烘帧」管线。 |
| **不局限于此** | 骨头真正强的是：**游戏运行时还在播骨骼**。跳到一半的姿势是算出来的，不是碰巧烘到的那一张。改抬腿高度，拉一根骨头就行，不用重画 12 张。 |
| **和「进 Godot 用帧图更流畅」的差距** | 烘成 8 张再 `AnimatedSprite2D`，流畅度 ≈ 这 8 张拍得好不好。烘少了，**仍会一顿一顿**。像素风时，骨头一转，格子还可能拧糊，有人反而不如烘成整像素帧。 |
| **对照（不是劝你放弃骨头）** | 最省事且往往最滑：Godot `Skeleton2D`（或 Spine 运行时）直接播。你要的帧图仍导出一份，当备份、当残影、当以后给别人看的表。 |

**结论：跟着你走锁骨。** 麻烦换来的是「永远同一只猫 + 能改动作」。  
请把顺序记成：

```
定皮 → 拆件 → 绑骨 → 做动画（正本）→ 导出帧/表/未分割（备份）
         ↑ 游戏里优先播这里
```

不要记成：绑完就扔掉骨头，只把表塞进 Godot。

像素还是插画：插画/更清楚的猫更适合「活骨骼」（旋转不会毁格子）。若你锁死现在这张粗像素，烘帧有时更干净。皮选定了再选「活播还是烘帧进玩家」。

### 4.4 导出帧图 / 未分割 / 精灵表（备份）

4. 脚对齐、画布大小固定（和黑骑士一样，避免进 Godot 后脚滑）

以后若要用 `AnimatedSprite2D` 播这些帧：SpriteFrames 里动作名仍用 `Idle` / `Walk`，导入像素图时 Filter = Nearest。

## 6. 特效不要画进帧图

你点名的规矩：**除了你要求的，不要往猫图上加别的特效。**

| 想要的效果 | 画进 PNG？ | 在哪做 |
|------------|------------|--------|
| 猫走路、跳、冲、滑的姿势 | 要（只改四肢和尾巴） | 骨骼 + 导出帧 |
| 残影 | **不要画** | 游戏里生成，现在就有 `spawn_one_afterimage()` |
| 刀光 | **不要画进走/站帧** | 攻击时另开一层（见 [[第9课-刀光与残影不是同一套]]） |
| 火花、烟、疾风线、光晕 | **不要画** | 以后用粒子（`GPUParticles2D` 一类） |

人话：帧图里最好永远是「干净的一只猫」。残影、粒子叠在游戏层上，才能开关、调颜色、换手机也不用重画 12 张带拖影的图。

## 详细代码解释

工程里**还没有**猫的骨头。下面用你**现在真实存在的行**说明：Godot 现在怎么播画面、为什么帧会僵、以后骨骼播法和烘帧存盘长什么样。

### A. 现在脚本抓住的是「换 PNG 的那一层」


| 词 | 人话 |
|----|------|
| `@onready` | 等场景节点都准备好，再执行这行 |
| `var anim` | 变量名叫 anim（animation 的缩写，动画） |
| `AnimatedSprite2D` | 会按时间换图的 2D 精灵 |
| `$AnimatedSprite2D` | 找**这个玩家自己身上**名叫 AnimatedSprite2D 的孩子 |

**语法点：** `$` 是 Godot 快捷写法。`:` 后面写类型。`=` 右边是要抓的节点。

### B. 进游戏先播待机——没有按跳去切 Walk

```415:418:C:\Users\yehai\Documents\firebot\Scene\fighter_player.tscn

sprite_frames = SubResource("SpriteFrames_618we")
```

| 词 | 人话 |
|----|------|
| `sprite_frames` | 一本字典：Idle 有哪些图、Jump 有哪些图 |
| `animation = &"Jump"` | 编辑器里当前预览可能停在 Jump |
| `autoplay = "Idle"` | **游戏一开始强制播 Idle** |
| `&"Jump"` | StringName，专门当名字用的字符串 |

**人话：** 你在编辑器里就算点着 Jump，运行后仍从 Idle 开始。脚本里又没有 `anim.play("Jump")`，所以**跳起来人可能还在播待机**——这和「帧僵不僵」是另一件事，但说明：Godot 不会替你「生成」一套跟手感匹配的动画。

**语法点：** `parent="."` 的 `.` 表示父节点是这个场景的根（玩家）。引号里的 `Idle` 必须和 SpriteFrames 里某条 `"name"` 完全一样。

### D. 真正的「跳」在改速度，不在换图

```56:58:C:\Users\yehai\Documents\firebot\Sprite\fighter_player.gd

	if is_on_floor():

```

| 词 | 人话 |
|----|------|
| `func` | 定义一个功能 |
| `_try_jump` | 名字前面的 `_` 常表示「内部用」 |
| `is_on_floor()` | 脚有没有踩着地 |

**人话：** 按空格人会飞，是因为改了 `velocity.y`。画面跳不跳，是另一层的事。所以锁骨、烘帧、换猫，**都不必改这三行**（除非以后要「起跳瞬间切 Jump 动画」——那是在这后面**加** `play("Jump")`，不是改飞的公式）。

**语法点：** `if` 条件成立才跑下一行。`()` 表示调用这个功能。`=` 是赋值。

### E. 以后活骨骼：播的是时间轴，不是下一张 PNG

现在工程里没有这几行。签字后会接近：

```gdscript
@onready var anim_player: AnimationPlayer = $AnimationPlayer

func _try_jump() -> void:
	if is_on_floor():
		velocity.y = jump_velocity
		anim_player.play("Jump")  # 多出来的：让画面也跳
		return
```

| 词 | 人话 |
|----|------|
| `AnimationPlayer` | Godot 自带的时间轴播放器，能转骨头、也能改位置 |
| `play("Jump")` | 开始播名字叫 Jump 的那一条 |

**人话：** `velocity.y` 还是飞。`play("Jump")` 让骨头从蹲到伸。两帧关键帧之间，引擎会插入很多中间姿势——**这才是比精灵表更流畅的那一块。**

**语法点：** `"Jump"` 必须和 AnimationPlayer 面板里那条动画名字一样。`.` 是「点谁身上的功能」：`anim_player` 的 `play`。

### F. 烘帧备份：把某一瞬间存成 PNG

也不要现在塞进玩家。练习场景里以后可以是：

```gdscript
func save_one_frame(path: String) -> void:
	var tex: ViewportTexture = $SubViewport.get_texture()
	var img: Image = tex.get_image()
	img.save_png(path)
```

| 词 | 人话 |
|----|------|
| `path` | 要存到硬盘的路径，比如 `user://walk_03.png` |
| `String` | 一串文字 |
| `ViewportTexture` | 「小摄像机拍到的画面」当成一张图 |
| `SubViewport` | 只渲染猫的小视口，免得把整个游戏窗口拍进去 |
| `get_image()` | 把贴图变成可存盘的像素 |
| `save_png` | 存成 PNG |

**人话：** 骨头走到某一格，拍一张，就是你要的「对应的帧图」。连着拍再拼，就是未分割 / 精灵表。**拍完之后，骨头场景仍要留着。**

**语法点：** `-> void` 表示做完不返回值。`$SubViewport` 是找子节点。`:` 左边是变量名，右边是类型。

### H. 残影已经在游戏里生成——所以不要画进帧图

```89:107:C:\Users\yehai\Documents\firebot\Sprite\fighter_player.gd
	var ghost := Sprite2D.new()
	ghost.texture = tex
	ghost.global_position = anim.global_position  # 停在「现在这个位置」
	ghost.flip_h = anim.flip_h                    # 左右朝向一致

	if parent_node:
		parent_node.add_child(ghost)
	else:
		add_child(ghost)

	# 5) 用 Tween 把透明度收到 0，然后删掉节点
	var tween := ghost.create_tween()
	tween.tween_property(ghost, "modulate:a", 0.0, ghost_lifetime)
	tween.finished.connect(ghost.queue_free)
```

| 词 | 人话 |
|----|------|
| `ghost` | 影子、残影这个临时节点 |
| `Sprite2D.new()` | 新建一个只会贴一张图的节点 |
| `modulate` | 给整张图乘一个颜色（含透明度） |
| `Tween` | 在一段时间里把某个数字慢慢变过去 |
| `modulate:a` | 只改透明度（a = alpha = 不透明度） |
| `queue_free` | 下一帧把这个节点删掉 |

**人话：** 按 Climb（W）时，游戏当场复制一张猫、弄半透明、再淡掉。所以烘帧时**不要**把残影画进 PNG，否则游戏再生成一次，会叠两层脏影子。

**语法点：** `"modulate:a"` 中间的 `:` 表示「这个颜色里的 a 通道」。`0.0` 是全透明。`ghost_lifetime` 是淡多久。

### I. 其它特效用粒子（现在不要加进玩家，先认字）

| `GPUParticles2D` | Godot 用显卡画很多小点点的节点（粒子） |
| `emitting` | true = 开始喷；false = 停 |

**人话：** 粒子是游戏层，想关就关、想换颜色改一个数。画进帧图就等于焊死在猫身上。

**语法点：** `$DashDust` 是找名叫 DashDust 的子节点。`true` / `false` 是开/关。

## 问答记录

**Q（2026-08-15）：想法是锁骨，做出动画，再弄帧图、精灵表、未分割图。麻烦但 Godot 里会更流畅。你怎么看？**  
**A：** 大方向对。骨头能让动作顺、永远同一只猫。Godot 播帧不会自动补中间帧，所以「只烘几张再 AnimatedSprite2D」仍可能顿；更流畅的是游戏里直接播骨骼，帧/表当导出备份。皮定了再拆件。正本必须能拉骨，不要只留 PNG。

**Q（2026-08-15 检查题）：走路只烘 8 张，第 3.5 步姿势从哪来？**  
**A（徒弟）：** 第三张，因为要等到转换成第四张。  
**师傅：** 大意对——3.5 还是第三张，Godot 不会造一张「3 和 4 之间的腿」。用词上不是「第四秒」：切下一张是按动画速度（比如每秒 8 张，大约 0.125 秒换一张），不是墙上的钟走到第 4 秒。活骨骼才会真的出现 3.5 那个中间姿势。

**Q（2026-08-15）：骨骼真的要删吗？想按 idle 文件夹放帧图、精灵表、未分割图、骨骼、动画。特效不要往图上加，粒子和残影在游戏里做。**  
**A：** 骨骼不要删，整理进各动作的 `骨骼/`。已按你的五格建好 idle/walk/jump/dash/slide/climb。走/站帧不要画残影火花。刀光另说，见第9课。残影用现有 `spawn_one_afterimage`。

**Q（2026-08-15）：刀光要，残影代码行不行？大佬怎么做？**  
**A：** 见 [[第9课-刀光与残影不是同一套]]。生成不了；另层弧光。
