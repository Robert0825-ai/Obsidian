## 设计原因

徒弟心是**类恶魔城**，手要先**短关卡**，因为后面会怎样还不确定。这和旧 GDD「首版不做完整恶魔城」一致，也和独立游戏常见做法一致：先验证跳/冲/滑/打好不好玩，再把房间连成能回去的大地图。

执着骨骼有两层：

1. **对：** 骨头解决「逐帧不连续、每张不像同一只」。正本留骨骼，表当导出。  
2. **担心 Godot 做不到、要换 Unity（C# 更强）：** 对**你这款 2D 横版**来说，不够成为换引擎的理由。类恶魔城要的是：房间、门、能力开关、TileMap、角色身体。这些 Godot 4 都有。C# 强在超大 3D、特定中间件、已有 C# 团队；不是「2D 猫跳得更真」。换 Unity 会把 firebot 第1～4课和触屏白做一遍。骨骼（Skeleton2D / Spine）两个引擎都能绑。

Unity **能**做类恶魔城，而且教程、资源商店更多——这是事实，不拦你以后学。**现在这款游戏用 Godot 能做完到 Steam 体量**；卡的是内容和范围，不是 GDScript 比 C# 慢。

```1:6:C:\Users\yehai\Documents\firebot\Sprite\fighter_player.gd
@onready var anim: AnimatedSprite2D = $AnimatedSprite2D
```

| 词 | 人话 |
|----|------|
| `CharacterBody2D` | 2D 会撞墙、能 `move_and_slide` 的角色身体 |
| `AnimatedSprite2D` | 现在的换图层；以后可换成骨骼 |

**人话：** 类恶魔城还是这具身体在走。Unity 里对等的是 `CharacterController2D` / `Rigidbody2D` 一类。换引擎是把这套**重写**，不是自动更流畅。

**语法点：** `extends` = 我是哪种节点。`$AnimatedSprite2D` 找自己身上的孩子。

### B. 真正跳起来的是改速度

```56:58:C:\Users\yehai\Documents\firebot\Sprite\fighter_player.gd
func _try_jump() -> void:
	if is_on_floor():
		velocity.y = jump_velocity
```

**人话：** Godot 已经在做「跳」。恶魔城多出来的是「二段跳当成一把钥匙去开高台」，公式还是这三行，只是以后加「学会了才能用」。

**语法点：** `is_on_floor()` 脚踩地。`velocity.y` 竖直速度。负数往上。

### C. 地图地块 Godot 里已有

工程里测试场已有 `TileMapLayer`（`Scene/node_2d.tscn` 约第 7 行）。

**人话：** 类恶魔城的房间就是很多地块拼起来，再加门。Unity 用 Tilemap，Godot 用 `TileMapLayer`，干同一件事。

**语法点：** `TileMap` 是旧名；Godot 4.3 起常用 `TileMapLayer`（一层地砖）。

### D. 以后「这扇门要有冲刺才能进」（现在不要写进玩家）

```gdscript
# 以后：门检查玩家有没有某项能力，不是检查是不是 Unity
if player.has_ability("Dash"):
	open()
```

**人话：** 恶魔城的核心是**能力开关**，几行判断。跟 C# / GDScript 哪门语言无关。

**语法点：** `"Dash"` 是能力名字，最好和输入动作名同一套字。
