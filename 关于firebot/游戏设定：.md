## 1. 执行摘要（Elevator Pitch）

**firebot** 是一款以 **火柴人** 为视觉主体的 **横版动作短关卡** 游戏（类动作 / 轻量探索雏形，**非**完整银河城首发）。

玩家在短平台关卡中完成移动、跳跃与近战攻击，击败少量敌人并抵达终点。产品优先保证 **PC 与 Android 同一套工程可玩**，再为未来移植微信 / 抖音小游戏预留架构习惯（触控、包体、性能），以获取更多测试用户。

一句话：

> 用最小完整循环验证「火柴人手感 + 双端可测」，再迭代内容体量。

## 2. 背景与原因（Why）

### 2.1 立项原因

1. **个人能力匹配**：制作人暂不强依赖手绘；火柴人 + 骨骼摆姿（Pivot）可快速产出可动画角色。  
2. **工具链已具备**：Godot 4.7、Pivot Animator v5、本机 ComfyUI、免费素材站可及。  
3. **学习曲线可控**：相对完整类恶魔城 / 格斗网游，短关卡动作的完成概率更高。  
4. **测试渠道现实**：第一阶段用 PC 安装包与 Android APK 找真人试玩；小游戏平台作为中后期渠道，不阻塞首版。

### 2.2 明确不做的事（首版 Out of Scope）

| 不做 | 原因 |
|------|------|
| 完整类恶魔城大地图 | 内容量过大，首版易烂尾 |
| 联网对战格斗 | 同步与平衡成本高 |
| 微信 / 抖音小游戏首发 | 平台适配与审核独立于核心玩法 |
| Spine / Blender 重管线 | 首版 ROI 低，延期引入 |
| 以 ComfyUI 批量生成进游戏序列帧 | 一致性与授权成本高，首版不用 |

## 3. 产品目标（Goals）

### 3.1 业务 / 学习目标

| ID | 目标 | 成功标准 |
|----|------|----------|
| G1 | 完成「可分发」的最小游戏 | 他人无需编辑器即可游玩（exe 或 apk） |
| G2 | 验证双端操作模型 | 同一工程支持键鼠 + 触屏基础操作 |
| G3 | 建立可持续迭代节奏 | 2 周内跑通垂直切片（Vertical Slice） |
| G4 | 积累测试反馈 | ≥ 3 名外部玩家完成一局并给出意见 |

### 3.2 体验目标（Player Experience Goals）

1. **3 秒懂操作**：移动 / 跳 / 攻击反馈明确。  
2. **30 秒进入战斗**：尽快碰到敌人或机关。  
3. **5～10 分钟打完一局**：适合碎片时间与小游戏心态。  
4. **失败可快速重来**：死亡 → 重开关卡成本低。

### 3.3 非目标（Non-Goals）v1.0

- 不追求 Steam 首发品质美术  
- 不追求数值养成深度  
- 不追求叙事长线

## 4. 目标平台与兼容策略

### 4.1 平台路线图

| 阶段 | 平台 | 形式 | 优先级 |
|------|------|------|--------|
| P0 | Windows PC | 导出可执行文件 | 必须 |
| P0 | Android | APK / 内测分发 | 必须 |
| P1 | Web（HTML5） | 浏览器试玩（如 itch） | 重要 |
| P2 | 微信小游戏 / 抖音小游戏 | 平台适配移植 | 延后 |

### 4.2 兼容原则（现在就要遵守）

1. **一套逻辑，多套输入**：`Input` 抽象为「左/右/跳/攻」，键鼠与虚拟按钮共用。  
2. **分辨率自适应**：`canvas_items` + `expand`（工程已启用），UI 使用锚点与最小点击热区（建议 ≥ 44px）。  
3. **横屏优先**：动作横版默认 Landscape（例如逻辑分辨率 1280×720）。  
4. **性能预算**：Mobile 渲染器；同屏特效与敌人数量设上限。  
5. **小游戏预留**：避免强依赖桌面独有 API；资源注意体量与加载分片（P2 再强化）。

> 说明：微信 / 抖音小游戏 **不等于** 导出 Android；需额外适配与审核。首版以 PC+Android 获取测试用户为先。

| 项 | 内容 |
|----|------|
| 类型 | 2D 横版动作 / 短关卡 |
| 视角 | 侧视 |

## 6. 核心玩法设计

### 6.1 玩家角色

| 属性 | v1 规格 |
|------|---------|
| 形态 | 火柴人（可略加粗肢体） |
| 生命 | 固定生命值或爱心数（如 3） |
| 移动 | 左右移动，地面摩擦简洁 |
| 跳跃 | 单段跳（二段跳列为 v1.1） |
| 攻击 | 近战挥击 1 种（有前摇/判定帧/后摇，可用简化） |
| 受击 | 短暂无敌帧 + 击退（可选简化） |

### 6.2 敌人（v1）

| 敌人 | 行为 | 目的 |
|------|------|------|
| 巡逻怪 A | 左右巡逻，碰触伤害 | 教「时机与攻击」 |
| （可选）投掷/静止危险 | 地刺 / 掉落 | 教跳跃 |

BOSS：v1 可用「加强版巡逻怪」或「终点前精英」代替完整 BOSS 战。

### 6.3 关卡结构（v1）

- 房间数：2～3 个短室，或 1 条连贯关卡  
- 元素：地面、平台、缺口、刺、检查点（可选）  
- 胜利：触达终点旗帜 / 门  
- 失败：生命归零 → 显示结算 → 一键重开  

### 6.4 进度与系统（v1 极简）

| 系统 | v1 |
|------|-----|
| 存档 | 可不做；或仅「本机关卡重来」 |
| 升级养成 | 无 |
| 商店 | 无 |
| 剧情 | 无或一行标题文案 |

## 7. 美术 / 音频 / 外包策略

### 7.1 原则

> **进游戏资源：下载或 Pivot 制作；宣传图：ComfyUI。**

### 7.2 资源来源矩阵

| 资源类型 | 来源 | 工具 / 站点 | 备注 |
|----------|------|-------------|------|
| 角色动画 | 自制或 CC0 包 | Pivot Animator v5；或 RGS_Dev 等 itch CC0 | 导出序列帧 → Godot `AnimatedSprite2D` / `SpriteFrames` |
| 地块 / 道具 | 免费可商用包 | Kenney、itch（核对 License） | **同一套风格**，禁止混搭 |
| UI | 引擎控件 | Godot Control | 大按钮、高对比 |
| 攻击特效 | 粒子或短序列帧 | Godot GPUParticles2D / 简单 PNG | 可后补 |
| 音效 | 免费库 | freesound、Kenney Audio | 注意授权 |
| BGM | 可选 | itch 免费 melodic 短环 | v1 可静音 |
| 应用图标 / 海报 | AI | 本机 ComfyUI | **不**用于关卡内动画帧 |

### 7.3 明确禁止（v1）

- 未核对商用许可的素材  
- 仿冒知名 IP 火柴人形象与名称  
- 破解版商业软件产出的工作流依赖

### 8.3 关键系统模块

| 模块 | 职责 |
|------|------|
| PlayerController | 移动、跳、攻、状态（Idle/Run/Jump/Attack/Hurt/Dead） |
| EnemyBase | 巡逻、伤害、死亡 |
| Level / Room | 碰撞与触发（终点、伤害区） |
| GameManager / UI | 生命、暂停、胜负、重开 |
| TouchControls | 移动端虚拟键（可做成 CanvasLayer） |

### 8.4 输入映射（逻辑层）

> **完整默认表（以工程为准）：** [[按键绑定]]  
> Cursor 规则：`firebot-input-defaults`（写脚本必须用下表动作名）

| 动作名（InputMap） | PC 默认 | 用途 | 移动端（预留） |
|--------------------|---------|------|----------------|
| `Left` / `Right` | A/D，←/→ | 左右移 | 左/右虚拟键或摇杆 |
| `Climb` / `Down` | W/S，↑/↓ | 上/下；**左右 + S = 滑铲** | 上/下按钮 |
| `Jump` | Space | 跳 | 跳按钮 |
| `Attack` | F，鼠标左键 | 攻击 | 攻按钮 |
| `Combo` | V | 连招 / 调试开关 | 连招按钮 |
| `Dash` | Shift，C | **冲刺 = 闪避** | 冲刺按钮 |
| （组合）左右 + `Down` | A/D 或 ←/→，再按 S | **滑铲** | 滑铲手势/按钮 |
| `Pause` | Esc | 暂停 | 暂停按钮 |
| `Interact` | E | 互动（预留） | 互动按钮 |

首页场景：`Scene/main_menu.tscn`（展示键位 + 进入测试场）。

**手机：** 不绑物理键盘；用 `Scene/ui/touch_controls.tscn` 虚拟键注入同一套动作名（清单见 [[按键绑定]]，原理见 [[输入-PC与手机同一套动作]]）。玩家脚本不因平台分叉。

## 9. 范围与里程碑（Roadmap）

### 9.1 里程碑总览

| 里程碑 | 名称 | 目标 | 建议周期 |
|--------|------|------|----------|
| M0 | 工程基线 | 仓库、分辨率、输入框架、空场景可运行 | 1～2 天 |
| M1 | 垂直切片 | 可走跳攻 + 1 敌 + 1 条关卡可通关 | 约 1 周 |
| M2 | 双端可测包 | Windows 包 + Android APK；触控可用 | 约 1 周 |
| M3 | 外部试玩 | ≥3 人反馈，整理问题列表 | 持续 |
| M4 | 内容小扩 | 第 2～3 房 / 精英敌；准备宣传图 | 视反馈 |
| M5 | 渠道预研 | 评估 HTML5 / 小游戏适配成本 | 延后 |

### 9.2 M1 验收标准（Definition of Done）

- [ ] 玩家可移动、跳跃、攻击  
- [ ] 至少 1 种敌人可被击败  
- [ ] 存在可抵达的胜利条件  
- [ ] 死亡可重开  
- [ ] 无阻塞性崩溃（正常游玩路径）  

### 9.3 M2 验收标准

- [ ] Windows 导出可在无编辑器机器运行  
- [ ] Android 导出可安装运行  
- [ ] 触屏可完成一局（不强制键鼠）
