# 09 · 模型怎么用（美术生产）

日期：2026-08-16  
来源：他看了 Cursor 模型列表后拍板。对照 [[08-素材卡住与止损]] · [[00-视觉宪法]] · [[07-出图走哪条软件]]

---

## 一句话

**不要追求最强模型。** 缺的不是「永远用 Opus」，是把最强的那几次用在最值得的 10 次机会里。  
目标是：生成**方案**、改设计、推进生产——选性价比。日常默认仍是 Grok 写代码；**美术标准不由 Grok 拍板。**

## 和写代码不一样

他需要的是：

- 能读几十页美术规范（宪法、色板、第一章方案）
- 能保持风格一致（必须统一，不是「这个也不错」）
- 能拆素材清单
- 能改 Prompt
- 最好能看图评价

不是：一次 Prompt 出商业级可拼接成品。

## 排序（他拍板）

| 名次 | 模型 | 档位 | 干什么 |
|------|------|------|--------|
| 1 | **Fable 5** | 日常 **Medium**；重要设计 **High** | 当美术总监：方案、拆清单、检查生成、改文档 |
| 2 | **GPT-5.6 Sol** | — | 审查设计文档、改 Prompt、写生产计划、找不合理 |
| 3 | **Cursor Grok 4.6** | — | 快问、头脑风暴、多个方案；**不负责最终美术标准** |

**不要长期用：**

- **Fable Max** — 预算吃不住
- **Opus 5 量产** — 不是它不好。一次「设计整个森林」会很爽，后面 200 张素材、100 次修改会爆。而且「只有它达到标准」会让人忍不住一直用

## 怎么分配额度

| 阶段 | 模型 | 只准干这些 |
|------|------|------------|
| 总监（每月少量） | **Opus 5** | 第一章整体审查、核心风格、大方向。例如：林子是不是太幼稚、黑猫和环境融不融、第一章情绪对不对 |
| 日常生产 | **Fable 5 Medium / High** | 素材清单、Prompt 优化、检查生成结果、改设计文档 |
| 普通任务 | **GPT-5.6 Sol / Grok 4.6** | 小改、翻译 Prompt、写说明 |
| 代码实现 | 按工程规则（难活用 Fable/Opus；日常 Grok） | 不要用贵模型刷灌木 |

按任务对照：

| 任务 | 模型 |
|------|------|
| 森林风格拍板 | Opus 5（少量） |
| 美术方案调整 | Fable 5 High |
| Prompt 优化 | GPT-5.6 Sol |
| 代码实现 | 日常 Grok；难活 Fable / Opus |
| 日常问答 | Grok 4.6 |

## Codex 是什么水平（生成素材）

他问过：Codex 也用 Agent，能不能更细致、更精致、没有 AI 味？

**不能靠它解决 AI 味。** Cursor 里的 Codex（如 GPT-5.3 Codex）是 **写代码的 Agent 模型**，不是画师。官方定位：多步改仓库、调试、工具调用；大约 Opus 三分之一价的日常代码。它能**看图**（截图、UI），返回的是文字和代码，不是一张更精致的像素。

同一套 Cursor Agent 工具（GenerateImage、Aseprite MCP、Godot）换 Codex 去「生成素材」时：

- 出 PNG 仍走**同一个出图引擎** → 海报味、发明宝石门光，还在
- 它更强的是：按母版切砖、写导入脚本、接 TileMap、把 Kenney/黄金样板铺进关
- 用脚本一格格填颜色：会更听话跟格子，但那是程序员砖，不是苔石那种手绘精致；我们已经用 Lua 填过，难看的是策略，不是「Agent 不够强」

结论：Codex 放在 **代码实现**（他表里那格）。黄金样板仍少量 Opus / Fable High。不要指望切到 Codex 就没有 AI 味。

## 为什么猫好看、林子却是 AI 味（2026-08-16）

不是算力跟不上。对话模型和出图模型是两套东西。Cursor 里换 Opus / Grok / Codex，**画 PNG 多半仍走同一个出图引擎**。贵的是「想得细、跟得住规范」，不是突然换了一块更强的画图 GPU。

### 猫为什么一开始就漂亮

- 考的是 **一只角色**：侧面、灰底、同一只黑猫，只改姿势。出图模型最熟的就是「一张角色设定图」。
- 有 **锁图**（A 暂定皮 / idle），每张都对着同一张抄。
- 进游戏前还有对齐、脚线、体量检查，难看的帧会打回。看起来漂亮，不全是「第一次生成就完美」。

### 林子为什么一做就翻

- 考的是 **一套砖**：同色、同格、能拼、能重复两百次。出图模型训练和点赞的是「一张好看的图」，不是 32×32 可拼接地砖。
- 没有先锁 4 个母版再扩展，而是每张都当独立海报（灰底正中一件）。
- 还用猫的高密度去要求石头、门、叶帘「一样精致」→ 模型只会画概念图，发明宝石和门光。
- 第一次 32 格是脚本填斜线，那是程序员砖，和猫不是同一条路。

### 为什么觉得 Opus 5 差距那么大

Opus 更会当总监：跟住几十页规范、更敢说「这张不行」、提示词更死、一次少画。  
不是它的像素算力碾压。用 Opus 去量产 200 张林子，走的还是「Prompt → 成品」，AI 味仍会回来。差距在 **怎么用**，不在显卡。

## 素材生成怎么处理（2026-08-16）

不走「谁强谁画 200 张」。分三层：

| 层 | 是什么 | 谁做 | 进不进游戏 |
|----|--------|------|------------|
| **能玩** | 齐的砖 / 买的包（现在 Kenney 草地）+ 已有 A 猫 | Grok 接进 Godot、铺关 | 进。临时皮，可换 |
| **拍板** | 黄金样板最多 4 个：草砖、石、树、背景层 | **Opus 5 少量** 出规格或审图；Fable 5 写清单/验收 | 签字后才当锁 |
| **扩展** | 其余砖、道具、NPC 站图 | 人 / Aseprite 照母版扩；或整套换包再改色 | 过 [[05-工程命名与验收]] 才进第一章 |

Grok **可以**：接包、抠图、建场景、写 `watch.html` 并打开给他看、说某张有 AI 味。  
Grok **不可以**：把生成海报当终皮、用脚本填格子当成品、不定终皮。

出图模型若再生成：只当概念/对照，灰底展示，没签字不覆盖 `idle.png`、不换玩家。

需要 Opus/Fable 时：Grok 开口 + 交接稿，只带笔记，不灌聊天。

## 出图舒不舒服（2026-08-16 他问）

他觉得灰底游戏素材「还可以」，问这是不是助手最不勉强的水平。

**是。** 舒适区 = 灰底单件（剑、盔甲、一棵树、一只猫的一帧）。不舒适 = 能拼接的砖、锁猫动画、整座林。没把握必须先说，规则 `say-when-unconfident`。

舒适区**不准默认成马里奥风**（1-UP 菇、亮绿圆丛、Kenney 当生成参考）。要用必须先申请。规则 `no-mario-style`。工程里 Kenney 临时砖只铺关。

同一段出图若连换画风、连加禁令：先提醒「规矩叠多了会画窄」，见 `remind-constraint-spiral`。不要等他自己倒推到累。

## 跑通之后怎么换皮（他问：要生成什么、怎么连成一体）

玩法跑通后，**不要直接问 Opus「把森林画了」。** 顺序是：

1. **Grok 读工程**：场景里实际用了哪些砖、猫多大、相机多少。现在例如 `Scene/forest_playable.tscn` 只用 Kenney `tile_0018` 放大 4 倍当草地，猫是 `cat_player`。
2. **Fable 5 High 归纳**：对照 [[04-第一章出场物清单]] + 工程，写出「要哪些素材、每张什么尺寸、左右怎么接、和猫同一套光/色」。这叫连成一体的规格，不是 200 张图。
3. **Opus 5 少量生成**：只按那份规格出黄金样板（草/石/树/远景），他签字后再扩、再替换 Kenney。

连成一体靠的是规格（同一格、同一色盘、同一光），不是让 Opus 把 Kenney 和生成草混在同一屏。

## 好钢用在刀刃上（2026-08-16 下午他拍板）

该用 Opus 5 / Fable 5 就不丢脸。Grok 若觉得某活更适合它们，**必须开口**，并给一段可粘贴的交接稿。不要假装已经换了模型。

**不要打通整段聊天当记忆。** 贵模型按读入的字收费。把「我和 Grok 谈了一夜」整段贴进去，等于再买一遍聊天记录。记忆用 Rules + 本夹笔记。交接只带：2～5 篇笔记路径 + 一两句任务 + 约束（不要量产）。

交接稿模板：

```
你是 firebot 的（美术总监 / 架构）。不要重读我和 Grok 的聊天。
先只读 Obsidian：00-视觉宪法、09-模型怎么用-美术生产、（再加当时需要的 1～3 篇）
任务：（一两句）
约束：好钢用在刀刃；不要量产素材；输出方案/清单/审查。
工程：C:\Users\yehai\Documents\firebot
```

## 真正难的不是模型

「素材都不对」常常不是选错模型。

专业流程：**概念 → 选方向 → 母版 → 再扩展。**  
不是：**Prompt → 成品。**

第一次就要求一块石头：好看、像素正确、能拼接、和猫一致、商业级——这个难度极高。钱应花在 **黄金样板**，例如只让高级模型做这 4 个（决定整座林子）：

1. 一块草地 Tile  
2. 一块石头  
3. 一棵树  
4. 一个背景层  

然后其它模型 / 人 / Aseprite **照着扩展**。不要让任何模型直接量产 200 张「最终资产」。
