# 骨架、换皮、完美像素

日期：2026-08-15  
结论先说：**手感优先。** 跳、走、冲仍写在 `CharacterBody2D` 上，和现在 firebot 一样。骨架只负责「看起来像猫」。换皮换的是骨头上的图，不改跳跃公式。

## 这是完美像素吗？有必要吗？

**现在这张暂定皮不是严格的「完美像素」。**  
完美像素 = 每个色块都落在格子上、放大是方块、没有发糊的半透明边。AI 画的猫常有软边和细腻过渡，那是「像素风插画」，不是格子锁定的完美像素。

**上架不必追求完美像素。** 可爱、像同一只、动作清楚，比格子对齐更值钱。Celeste 一类会偏格子；很多能卖的独立游戏角色并不是严格完美像素。

若以后要更「格子感」，是小改描边/缩放，不是现在挡开工。

## 代码作用在骨架上吗？

**不。** 两层：

```
CharacterBody2D   ← 代码写这里：速度、跳、冲、碰撞。手感在这。
  └─ 画面（二选一或以后切换）
        AnimatedSprite2D  整张图一帧帧播
        或 Skeleton2D     骨头转动，零件图贴在骨头上
```

换皮方便，是因为 **零件图可以换、骨头动作可以留。** 不是因为跳跃写在骨头上。

## 会不会把体验弄烂？

手感（跳得高不高、滑不滑）：**不会**，只要继续 `move_and_slide()`，不把物理绑到骨头上。

画面：骨头一转，像素图容易发糊、出现「斜着的格子」。所以：

- **正本**仍是骨架（你能拉骨头改走、跳）。
- **游戏里**若转动看起来糊，再把骨架烘成帧，用 `AnimatedSprite2D` 播——和现在 fighter 播帧同一套，手感不变。
- 先在测试场看骨架直播行不行，不行再烘帧。**不替换**现有 `fighter_player.tscn`，直到你觉得猫比剑士好玩。

## 设定会不会变？

角色是谁（A 黑猫白手套无项圈、B 狸花、C 橘猫）一般不动。皮可以小改。所以更要骨架：改一张头、一条腿，不必重画整套走跳帧。
