## 1. 设计原因

玩家要看的是：**同一只红缨黑骑士，同一把银剑，只改姿势。**  
他指出攻击第 2 帧（蓄力）整个人和剑都小一号。这不是「蹲低一点」，是生成时画成了另一个体型。

旧检查用量「脚底到画面最高点」。蓄力时剑举过头顶，小骑士的剪影也会被剑撑满，高度看起来合格。检查等于没有。猫那边已经犯过「用量包围盒、斜着的猫面积假正常」；骑士举剑是同一类空转。

所以尺子改成三样**几乎不受姿势骗**的东西：

1. **盔甲像素**（去掉剑、白虚影、红缨）——人有多大  
2. **红缨宽度**——头有多大；缨往后飘可以变宽，但不能突然变窄一半  
3. **银剑像素**——武器有多长；白虚影那帧银光会爆，这项跳过  

和市面/旧方案的差：不是「看起来差不多高就过」，而是**人和剑分开锁**，并且留一张故意画小的坏例子，脚本必须先拦住它，才许查正式帧。

### 3.1 锁值写死在文件头

`knight_scale.py` 大约第 20–27 行：

```python
BODY_PX = 183521
PLUME_W = 208
SWORD_PX = 3253
BODY_MIN, BODY_MAX = 0.82, 1.18
PLUME_W_MIN, PLUME_W_MAX = 0.70, 1.40
SWORD_MIN = 0.55
```

| 名词 | 全称/来历 | 人话 |
|------|-----------|------|
| `BODY_PX` | body pixels，盔甲像素个数 | 待机那只人「身上有多少点」，不含剑 |
| `PLUME_W` | plume width，盔缨宽度 | 红缨左右占多少像素 |
| `SWORD_PX` | sword pixels，剑的银色点数 | 剑大不大；比量剑的包围盒稳 |
| `0.82～1.18` | 允许浮动 | 蹲会少一点面积，但不能少到六成 |

语法：`BODY_MIN, BODY_MAX = 0.82, 1.18` 是一次给两个名字赋值。后面用 `br < BODY_MIN` 判断「是不是太小」。

人话：这些数字是从待机锁图量出来的。换锁图就要重量，不能随手改。

### 3.2 先抠灰底，再把人拆成四堆

`knight_scale.py` · `occupancy` 大约第 30–32 行：

```python
def occupancy(arr: np.ndarray) -> np.ndarray:
    diff = np.abs(arr.astype(np.int16) - GRAY)
    return ~np.all(diff <= TOL, axis=2)
```

| 名词 | 人话 |
|------|------|
| `arr` | 整张图，每个点有红绿蓝三个数 |
| `GRAY` | 136，就是 `#888888` |
| `TOL` | 容差 22：灰得差不多的点当背景 |
| `~` | 取反：不是灰底的，才算「身上」 |

语法：`axis=2` 表示沿着颜色那一维看。三个通道都接近灰 → 这点是背景。

人话：灰底是看图用的，不算进「人有多大」。

---

`split` 大约第 35–43 行：

```python
plume = mask & (r > 120) & (r > g + 40) & (r > b + 40) & (g < 160)
ghost = mask & (r > 230) & (g > 230) & (b > 230)
silver = mask & (r > 170) & (g > 170) & (b > 160) & ~ghost
body = mask & ~plume & ~ghost & ~silver
```

| 堆 | 怎么认 | 人话 |
|----|--------|------|
| `plume` 缨 | 红很多、绿和蓝少 | 只有盔缨是绯红 |
| `ghost` 白虚影 | 三个通道都极亮 | 砍那一帧的白弧 |
| `silver` 剑 | 亮灰、不是纯白 | 刃；盔甲高光也会沾一点，所以只当「剑够不够大」的粗尺子 |
| `body` 盔甲 | 身上减去上面三堆 | **人有多大** 用这个 |

语法：`&` 是「并且」。`~ghost` 是「不要白虚影」。剑那行先去掉白，避免砍帧把白弧算进剑。

人话：蹲、举剑、披风扬起来，盔甲点数差不多还在；整只缩小，这个数会掉到 59% 那种，一眼假。

### 3.3 面积变了，边要开平方

`scale_to_idle_body` 大约第 65–75 行：

```python
s = float(np.sqrt(target_body / float(m["body"])))
im = im.resize((nw, nh), Image.Resampling.LANCZOS)
```

| 名词 | 人话 |
|------|------|
| `m["body"]` | 这一帧盔甲有多少点 |
| `sqrt` | 开平方。像素个数按面积变，边长按比例变 |
| `LANCZOS` | 一种缩小/放大算法，比硬取整格好看一点 |

语法：`target_body / m["body"]` 是面积比。边要放大多少 = 面积比开根。例如面积只有 1/4，边要放 2 倍。

人话：生成图若整只偏小，先按待机盔甲面积统一放大，再对脚。**不能**再用脚到剑尖当放大依据。

### 3.4 检查必须先咬死坏例子

`audit_knight_frames.py` · `main` 大约第 33–37 行：

```python
bad_issues = issues_against_lock("fixture_small_charge", Image.open(BAD))
if not bad_issues:
    print("EMPTY CHECK: _bad_small_02.png passed. Audit is broken.")
    return 2
print("FIXTURE_FAIL_OK")
```

| 名词 | 人话 |
|------|------|
| `BAD` | `_bad_small_02.png`，旧的小蓄力 |
| `issues_against_lock` | 对照待机锁，列出哪一项超标 |
| `return 2` | 脚本异常退出：检查自己坏了 |

语法：`if not bad_issues` 表示「一个问题都没报」。坏图居然合格 → 尺子失效。

人话：交帧前应看到两行：先 `FIXTURE_FAIL_OK`（坏的确实坏），再 `AUDIT_OK`（现在这五帧人和剑对得上）。只有第二行、第一行没有，不算过。

旧小帧实测：盔甲 59%、缨宽 53%，两项都应报。

### 3.5 游戏里砍完要回到站，判定不能整段开

`knight.gd` 大约第 19–20、85–86 行：

```gdscript
const HIT_FRAMES := [2, 3]

hitbox.monitoring = anim.animation == &"Attack" and anim.frame in HIT_FRAMES
```

| 名词 | 人话 |
|------|------|
| `HIT_FRAMES` | 名单：第 3 帧白虚影、第 4 帧定住（从 0 数是 2 和 3） |
| `hitbox` | 贴在剑前面的检测盒 |
| `monitoring` | 打开才真的检测「碰到木桩没有」 |
| `&"Attack"` | StringName，动画名字 |

语法：`anim.frame in HIT_FRAMES` = 当前帧号在不在名单里。`and` = 两样都要：正在播攻击，并且是砍的那两帧。

人话：举剑、收回碰不到人。白光扫过去和定住那一下才能打中。这和分镜「白虚影才是砍」是同一条设计。

朝左时身子不跑偏，大约第 60–63 行：

```gdscript
anim.flip_h = facing < 0
anim.offset.x = sprite_body_offset_x * facing
```

人话：图里人偏左、剑偏右。只翻图、不改偏移，人会离开碰撞盒。`facing` 朝右是 `1`、朝左是 `-1`，偏移跟着变号。
